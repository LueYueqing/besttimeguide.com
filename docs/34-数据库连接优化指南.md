# 数据库连接优化指南

## 问题诊断

### 症状
- Neon 数据库计算时间过高（10.26小时）
- 存在持续的数据库连接消耗资源

### 根本原因
项目中有 **38个文件** 都在各自创建新的 `PrismaClient` 实例，导致：
1. 每个文件独立创建数据库连接池
2. 连接未正确关闭，造成连接泄漏
3. 大量并发请求时创建过多连接，耗尽数据库连接限制

### 受影响的文件类型
- API路由（25个）
- 库函数（5个）
- 脚本文件（8个）

## 解决方案

### 1. 创建 Prisma 单例

创建了 `lib/prisma.ts` 文件，实现单例模式：

```typescript
import { PrismaClient } from '@prisma/client'

const globalForPrisma = global as unknown as { prisma: PrismaClient }

export const prisma =
  globalForPrisma.prisma ||
  new PrismaClient({
    log: process.env.NODE_ENV === 'development' ? ['query', 'error', 'warn'] : ['error'],
  })

if (process.env.NODE_ENV !== 'production') globalForPrisma.prisma = prisma

export default prisma
```

**优点：**
- 开发环境：防止热重载时创建多个实例
- 生产环境：全局唯一实例，共享连接池
- 自动管理连接生命周期

## 最佳实践

### 1. 新增代码规范

**❌ 错误方式：**
```typescript
import { PrismaClient } from '@prisma/client'
const prisma = new PrismaClient()
```

**✅ 正确方式：**
```typescript
import { prisma } from '@/lib/prisma'
```

### 2. 连接池配置

在 `lib/prisma.ts` 中可以根据需要调整连接池参数：

```typescript
new PrismaClient({
  log: process.env.NODE_ENV === 'development' ? ['query', 'error', 'warn'] : ['error'],
  datasources: {
    db: {
      url: process.env.DATABASE_URL,
    },
  },
})
```

Prisma 默认连接池配置：
- 生产环境：连接池大小 = CPU 核心数 × 2 + 1
- 开发环境：较小的连接池

## 后续优化建议

### 1. 连接查询优化

- 添加适当的数据库索引
- 使用 `select` 只查询需要的字段
- 避免N+1查询问题，使用 `include` 或 `select`

### 2. 缓存策略

已经实现的部分：

- ✅ 使用 cache tags 进行精确缓存失效

可进一步优化：
- 添加 Redis 缓存热点数据
- 实现更细粒度的缓存策略

### 3. 查询超时处理

已在 `lib/auth.ts` 中实现查询超时：

```typescript
const withTimeout = <T>(promise: Promise<T>, timeoutMs: number = 4000): Promise<T | null> => {
  return Promise.race([
    promise,
    new Promise<null>((resolve) => setTimeout(() => resolve(null), timeoutMs))
  ])
}
```

建议在其他长时间运行的查询中也使用此模式。

### 4. 批量操作

对于大量数据的操作，使用批量API：

```typescript
// ❌ 逐个插入
for (const item of items) {
  await prisma.item.create({ data: item })
}

// ✅ 批量插入
await prisma.item.createMany({
  data: items,
  skipDuplicates: true,
})
```
