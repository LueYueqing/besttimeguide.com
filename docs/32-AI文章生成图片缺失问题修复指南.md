# AI 文章生成图片缺失问题修复指南

## 问题描述

在 `/api/articles/ai-rewrite` 的文章生成流程中，发现很多文章生成后没有图片，例如文章 ID 214、204 等。根据设计，文章生成应该分两步走：

1. **阶段 1**：DeepSeek 生成文章内容和图片占位符
2. **阶段 2**：根据占位符从 Pixabay/Pexels/Unsplash 搜索图片，然后才正式发布

**现状问题**：很多文章在没有图片的情况下就被正式发布了，违反了两步走的流程设计。

## 问题原因

在 `app/api/articles/ai-rewrite/route.ts` 的第 267-273 行，存在一个错误的逻辑：

```javascript
if (placeholders.length > 0 && successCount === 0) {
  console.warn(`[图片补全] 文章 ${article.title} 未能匹配图片，将清理占位符`)
  currentContent = currentContent.replace(/!\[[^\]]*\]\(IMAGE_PLACEHOLDER_[^)]+\)\)/g, '')
}
```

这个逻辑的问题是：

1. **清理占位符**：当所有图片搜索都失败时（`successCount === 0`），代码会清理所有图片占位符
2. **直接发布**：清理占位符后，继续执行发布逻辑，将文章状态设置为 `completed` 并 `published: true`
3. **结果**：文章被发布，但内容中没有任何图片

### 为什么图片搜索会失败？

图片搜索可能失败的原因包括：

1. **API 密钥未配置**：Pixabay、Pexels、Unsplash 的 API 密钥可能未设置
2. **API 配额用尽**：免费账户的请求配额可能已经用完
3. **搜索关键词不匹配**：AI 生成的关键词可能太泛或太特殊，导致无法匹配到图片
4. **网络问题**：临时网络问题导致图片 API 调用失败
5. **图片源返回空结果**：即使 API 正常，也可能因为关键词不匹配返回空结果

### 错误流程示例

假设一篇文章有 3 个图片占位符：

```
![Beautiful view](IMAGE_PLACEHOLDER_1(tokyo skyline))
![City night](IMAGE_PLACEHOLDER_2(tokyo night))
![Cherry blossoms](IMAGE_PLACEHOLDER_3(cherry blossoms))
```

如果所有 3 个图片搜索都失败：

1. `successCount = 0`
2. 代码清理所有占位符：`currentContent = ''`（只有文本，没有图片）
3. 继续执行发布逻辑：`published: true, aiRewriteStatus: 'completed'`
4. **结果**：文章发布了，但没有任何图片

## 解决方案

### 修复逻辑

修改 `app/api/articles/ai-rewrite/route.ts`，当图片搜索全部失败时：

1. **不清理占位符**：保留图片占位符，便于下次重试
2. **不发布文章**：状态保持为 `pending`，而不是 `completed`
3. **允许重试**：后台任务下次运行时会再次处理这篇文章

```javascript
// 检查是否至少成功上传了一张图片
if (placeholders.length > 0 && successCount === 0) {
  console.error(`[图片补全失败] 文章 ${article.title} 未能匹配任何图片，保留占位符，状态重置为 pending`)
  // 保留占位符，不清理，以便下次重试
  // 不发布文章，状态设为 pending，让后台任务下次继续处理
  await prisma.article.update({
    where: { id: article.id },
    data: {
      content: currentContent,  // 保留占位符的内容
      aiRewriteStatus: 'pending',
      aiRewriteAt: new Date()
    }
  })
  console.log(`[AI 流水线] 文章 ${article.title} 因图片匹配失败已重置为 pending 状态`)
  return { id: article.id, slug: article.slug, title: article.title }
}

// 至少有一张图片成功上传，继续处理
// ... 原有的发布逻辑
```

### 修复后的行为

#### 场景 1：图片搜索全部失败

1. 检测到 `successCount === 0`
2. 保留图片占位符，不清理
3. 状态设为 `pending`，不发布
4. 后台任务下次会继续尝试
5. **结果**：文章不会发布，直到至少有一张图片成功

#### 场景 2：部分图片搜索成功（至少 1 张）

1. 检测到 `successCount > 0`
2. 替换成功的图片占位符为真实图片 URL
3. 失败的占位符保留（可以继续手动处理或后续重试）
4. 生成封面图
5. 状态设为 `completed` 并发布
6. **结果**：文章发布，至少包含 1 张图片

#### 场景 3：所有图片搜索成功

1. 所有占位符都被替换为真实图片 URL
2. 生成封面图
3. 状态设为 `completed` 并发布
4. **结果**：文章发布，包含所有预期图片

## 相关代码逻辑

### 图片搜索优先级

`searchImage` 函数会按以下顺序尝试搜索图片：

1. Pixabay（免费，优先级最高）
2. Pexels
3. Unsplash

对于每个占位符，会尝试多个搜索关键词组合：

```javascript
const searchSequences = [
  cleanKeywords,              // 占位符中的关键词
  cleanAlt,                   // Alt 文本
  `${cleanKeywords} ${titleWords}`,  // 关键词 + 标题
  titleWords                  // 标题关键词
]
```

### 状态流转

文章的 `aiRewriteStatus` 状态流转：

```
pending → processing → pending/completed → completed
         ↓
       failed → pending（可重试）
```

- `pending`：待处理
- `processing`：处理中
- `completed`：已完成（已发布）
- `failed`：失败（会自动转为 pending 重试）

## 影响和注意事项

### 正面影响

1. ✅ **确保文章质量**：没有图片的文章不会被发布
2. ✅ **符合设计流程**：严格遵守两步走的生成流程
3. ✅ **可重试机制**：失败的图片搜索可以自动重试
4. ✅ **更好的用户体验**：发布的文章都至少包含 1 张图片

### 需要注意的事项

1. **部分成功的情况**：如果只有 1-2 张图片成功（比如 3-5 个占位符），文章仍然会发布，但可能不是所有位置都有图片
2. **图片源配置**：需要确保至少配置了一个图片 API（Pixabay、Pexels、Unsplash）
3. **API 配额监控**：需要监控图片 API 的配额使用情况，避免用尽后导致大量文章无法完成
4. **关键词质量**：如果发现图片搜索频繁失败，可能需要优化 AI 提示词，生成更好的搜索关键词

### 处理已发布的无图文章

对于已经发布但没有图片的文章（如 ID 214、204 等），需要：

1. 手动检查这些文章
2. 重新生成内容（带图片占位符）
3. 或者手动补充图片

可以使用以下脚本重置这些文章：

```bash
# 重置特定文章，让 AI 重新生成（带图片占位符）
# 修改 aiRewriteStatus 为 'pending'，清空 content
```

或使用管理界面的"重新生成"功能。
