# 文章关联记录创建策略

## 方案对比分析

### 方案1: 文章创建/更新时实时生成
**时机**：每次创建或更新文章时立即生成关联

**优点**：
- ✅ 关联关系始终最新
- ✅ 不需要定时任务
- ✅ 实现简单

**缺点**：
- ❌ 每次发布都要计算，影响发布速度
- ❌ 如果文章很多，计算时间可能很长
- ❌ 阻塞用户操作

**适合**：文章数量少于500篇的网站

---

### 方案2: 定时任务批量更新
**时机**：每天凌晨/每周全量更新一次

**优点**：
- ✅ 不影响用户体验
- ✅ 可以错峰执行
- ✅ 适合大规模数据

**缺点**：
- ❌ 关联关系有延迟
- ❌ 需要配置定时任务
- ❌ 新文章的关联不会立即生效

**适合**：文章数量超过1000篇的网站

---

### 方案3: 按需生成（访问时）
**时机**：第一次访问文章详情页时生成

**优点**：
- ✅ 只生成真正需要的关联
- ✅ 节省计算资源

**缺点**：
- ❌ 首次访问慢
- ❌ 用户体验差
- ❌ 不适合正式环境

**适合**：开发测试环境

---

### 方案4: 混合方案（推荐）⭐
**时机**：
1. 文章发布/更新时：**异步生成**（不阻塞响应）
2. 定时任务：每天凌晨**全量更新**一次
3. API接口：管理员可**手动触发**刷新

**优点**：
- ✅ **实时性好**：新文章立即有关联
- ✅ **性能优异**：异步不阻塞，定时错峰
- ✅ **数据一致**：定时任务确保数据一致性
- ✅ **可控性强**：可手动干预
- ✅ **扩展性好**：适合各种规模

**缺点**：
- ⚠️ 实现相对复杂
- ⚠️ 需要配置定时任务

**适合**：**所有规模的网站**（强烈推荐）

---

## 推荐实施方案：混合方案

### 1. 异步生成（文章发布/更新时）

#### 实现方式A: 使用 Prisma 扩展（推荐）

```typescript
// lib/prisma.ts

import { PrismaClient } from '@prisma/client'

const globalForPrisma = global as unknown as { prisma: PrismaClient }

export const prisma = globalForPrisma.prisma || new PrismaClient({
  log: process.env.NODE_ENV === 'development' ? ['query', 'error', 'warn'] : ['error'],
})

if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma
}

// 扩展 Prisma 客户端，添加异步生成关联方法
export const prismaWithRelations = prisma.$extends({
  model: {
    $allModels: {
      async generateRelations(this: any, articleId: number) {
        // 使用 setTimeout 让执行延后，不阻塞当前请求
        setTimeout(async () => {
          try {
            console.log(`[Async] Starting relations generation for article ${articleId}`)
            
            // 导入生成函数
            const { generateRelationsForArticle } = await import('../scripts/generate-article-relations')
            await generateRelationsForArticle(articleId)
            
            console.log(`[Async] Relations generated for article ${articleId}`)
          } catch (error) {
            console.error(`[Async] Error generating relations for article ${articleId}:`, error)
          }
        }, 0) // 立即执行但异步
      }
    }
  }
})
```

```typescript
    prismaWithRelations.article.generateRelations(articleId)
  }
  
  return NextResponse.json({ success: true, article })
}
```

#### 批量更新脚本

```typescript
// scripts/update-all-relations.ts

import { PrismaClient } from '@prisma/client'
import { parseTags } from '../lib/article-tags'

const prisma = new PrismaClient()

/**
 * 为单篇文章生成关联关系
 */
async function generateRelationsForArticle(articleId: number) {
  const article = await prisma.article.findUnique({
    where: { id: articleId },
    include: { category: true },
  })

  if (!article) return

  // 删除旧关联
  await prisma.articleRelation.deleteMany({
    where: { articleId },
  })

  // 1. 同分类关联（权重100）
  const categoryPosts = await prisma.article.findMany({
    where: {
      id: { not: articleId },
      categoryId: article.categoryId,
      published: true,
      publishedAt: { lte: new Date() },
    },
    include: { category: true },
    orderBy: { publishedAt: 'desc' },
    take: 6,
  })

  for (const related of categoryPosts) {
    await prisma.articleRelation.create({
      data: {
        articleId,
        relatedArticleId: related.id,
        type: 'CATEGORY',
        weight: 100,
      },
    })
  }

  // 2. 同标签关联
  const articleTags = parseTags(article.tags)
  if (articleTags.length > 0) {
    const tagPosts = await prisma.article.findMany({
      where: {
        id: {
          notIn: [articleId, ...categoryPosts.map(p => p.id)],
        },
        published: true,
        publishedAt: { lte: new Date() },
      },
      include: { category: true },
      orderBy: { publishedAt: 'desc' },
      take: 10,
    })

    const tagMatches = tagPosts.map(post => {
      const postTags = parseTags(post.tags)
      const matched = articleTags.filter(tag => postTags.includes(tag))
      return {
        post,
        matchedCount: matched.length,
        matchedTags: matched,
      }
    })
    .filter(item => item.matchedCount > 0)
    .sort((a, b) => b.matchedCount - a.matchedCount)
    .slice(0, 3)

    for (const match of tagMatches) {
      await prisma.articleRelation.create({
        data: {
          articleId,
          relatedArticleId: match.post.id,
          type: 'TAG',
          weight: match.matchedCount * 10,
          matchedTags: JSON.stringify(match.matchedTags),
        },
      })
    }
  }

  return true
}

/**
 * 批量更新所有文章的关联关系
 */
export async function updateAllRelations() {
  console.log('[Batch] Starting article relations update...')

  const startTime = Date.now()
  let successCount = 0
  let errorCount = 0

  try {
    // 获取所有已发布文章
    const articles = await prisma.article.findMany({
      where: { published: true },
      select: { id: true, title: true },
      orderBy: { updatedAt: 'desc' },
    })

    console.log(`[Batch] Found ${articles.length} published articles`)

    // 逐个更新
    for (const article of articles) {
      try {
        await generateRelationsForArticle(article.id)
        successCount++
        
        // 每处理100篇打印一次进度
        if (successCount % 100 === 0) {
          console.log(`[Batch] Progress: ${successCount}/${articles.length} articles processed`)
        }
      } catch (error) {
        console.error(`[Batch] Error processing article ${article.id}:`, error)
        errorCount++
      }
    }

    const duration = ((Date.now() - startTime) / 1000).toFixed(2)
    console.log(`[Batch] Completed in ${duration}s`)
    console.log(`[Batch] Success: ${successCount}, Errors: ${errorCount}`)
    
    return {
      success: true,
      total: articles.length,
      successCount,
      errorCount,
      duration,
    }
  } catch (error) {
    console.error('[Batch] Fatal error:', error)
    throw error
  } finally {
    await prisma.$disconnect()
  }
}

// 如果直接运行此脚本
if (require.main === module) {
  updateAllRelations()
    .catch(error => {
      console.error('[Batch] Failed:', error)
      process.exit(1)
    })
}
```

### 3. API接口手动触发

```typescript
// app/api/admin/update-relations/route.ts

import { NextRequest, NextResponse } from 'next/server'
import { auth } from '@/lib/auth'
import { prisma } from '@/lib/prisma'

// 检查管理员权限
async function checkAdmin() {
  const session = await auth()
  if (!session?.user?.id) return null
  
  const userId = typeof session.user.id === 'string' 
    ? parseInt(session.user.id, 10) 
    : session.user.id
  
  const user = await prisma.user.findUnique({
    where: { id: userId },
    select: { isAdmin: true },
  })
  
  return user?.isAdmin ? userId : null
}

// POST - 手动触发全量更新
export async function POST(request: NextRequest) {
  const adminId = await checkAdmin()
  if (!adminId) {
    return NextResponse.json({ success: false, error: 'Unauthorized' }, { status: 401 })
  }

  try {
    // 异步执行（不阻塞响应）
    const { updateAllRelations } = await import('../../../scripts/update-all-relations')
    
    updateAllRelations()
      .then(result => {
        console.log('[Manual] Relations update completed:', result)
      })
      .catch(error => {
        console.error('[Manual] Relations update failed:', error)
      })
    
    return NextResponse.json({
      success: true,
      message: 'Article relations update started in background',
    })
  } catch (error) {
    console.error('[Manual] Error starting update:', error)
    return NextResponse.json(
      { success: false, error: 'Failed to start update' },
      { status: 500 }
    )
  }
}
```

```typescript
// 避免短时间内重复生成
const generating = new Map<number, boolean>()

export async function generateRelationsAsync(articleId: number) {
  // 如果正在生成，跳过
  if (generating.get(articleId)) {
    console.log(`[Skip] Article ${articleId} is already generating relations`)
    return
  }
  
  generating.set(articleId, true)
  
  try {
    // ... 生成逻辑 ...
  } finally {
    // 30秒后释放锁
    setTimeout(() => generating.set(articleId, false), 30000)
  }
}
```

## 总结

### 推荐方案：混合方案 ⭐

**三个触发时机**：
1. **文章发布/更新**：异步生成（实时性好）
2. **定时任务**：每天凌晨全量更新（数据一致）
3. **手动API**：管理员随时触发（可控性强）

**预期效果**：
- ✅ 新文章立即有关联（异步生成）
- ✅ 旧文章关联保持最新（定时更新）
- ✅ 不影响用户体验（异步不阻塞）
- ✅ 数据始终保持一致（定时全量更新）
- ✅ 可随时手动干预（管理员API）

**实施优先级**：
- **P0**：异步生成 + 查询函数更新
- **P1**：定时任务配置
- **P2**：监控和优化

这是最适合生产环境的方案！
