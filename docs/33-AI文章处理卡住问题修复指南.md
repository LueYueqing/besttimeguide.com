# AI 文章处理卡住问题修复指南

## 问题描述

在仪表板的草稿列表中，大量文章显示为"处理中"状态（蓝色标签），但文章内容迟迟没有生成。

## 根本原因

1. **Vercel Hobby 版本限制**：API 最大执行时间为 60 秒
2. **AI 生成超时**：DeepSeek 或 OpenAI API 响应时间超过 60 秒
3. **图片搜索失败**：Pixabay/Pexels/Unsplash API 超时或无结果
4. **状态未恢复**：当 API 超时后，文章状态仍然是 `processing`，但实际处理已中断

## 解决方案

### 1. 立即修复：批量重置卡住的文章

使用提供的脚本批量重置所有卡住的文章：

```bash
# 检查所有处理中的文章
node scripts/check-processing-articles.js

# 批量重置所有处理中的文章
echo yes | node scripts/reset-all-processing-articles.js
```

这个脚本会：
- 将所有 `processing` 状态的文章重置为 `pending`
- 清空内容和封面图
- 设置 `aiRewriteAt` 为 25 小时前（绕过 24 小时冷却期）
- 将文章设置为草稿状态

### 2. 前端手动重置

在仪表板中，每篇文章旁边有一个重置按钮（橙色图标）：
- 对于 `processing` 状态：点击后强制清空内容并重新生成
- 对于其他状态：点击后重新触发 AI 生成流程

## 预防措施

### 1. 优化 AI API 调用

#### 使用更快的模型
- `app/api/articles/ai-rewrite/route.ts` 中已优先使用 DeepSeek（比 GPT-4 快）
- DeepSeek 模型：`deepseek-chat`
- OpenAI 备用：`gpt-4o-mini`（比 `gpt-4` 快很多）

#### 添加超时保护
```typescript
// 在 ai-rewrite/route.ts 中已有超时保护
export const maxDuration = 60  // Vercel Hobby 最大值
```

### 2. 分阶段处理

AI 处理已分为两个阶段：

#### 阶段 1：生成文本
- 状态：`pending` → `processing` → `pending`（有内容）
- 优先处理没有内容的文章
- 超时风险：中等

#### 阶段 2：搜索并上传图片
- 状态：`pending` → `processing` → `completed`
- 优先处理有内容但没有图片的文章
- 超时风险：较高（图片搜索可能很慢）

#### 第三层防护
如果所有图片搜索都失败：
- 保留占位符格式
- 清空内容
- 重置为 `pending` 状态
- 让 AI 重新生成（可能使用不同关键词）

### 3. 监控和告警

#### 定期检查
```bash
# 每天检查一次卡住的文章
node scripts/check-processing-articles.js
```

#### 设置自动监控（可选）
创建 GitHub Action 或 cron job，每天自动检查并告警：
- 超过 1 小时的 `processing` 文章
- 超过 24 小时的 `failed` 文章

### 4. API 密钥管理

确保环境变量正确配置：
- `DEEPSEEK_API_KEY`：优先使用（速度快，成本低）
- `OPENAI_API_KEY`：备用方案
- `PIXABAY_API_KEY`：图片搜索
- `PEXELS_API_KEY`：图片搜索备用
- `UNSPLASH_ACCESS_KEY`：图片搜索备用

### 5. 前端优化

#### 自动触发 AI 处理
在 `app/dashboard/articles/articles-client.tsx` 中：
```typescript
useEffect(() => {
  // 管理员访问时自动触发 AI 处理
  if (user?.isAdmin) {
    fetch('/api/articles/ai-rewrite', {
      method: 'POST',
    }).catch(console.log)
  }
}, [user?.isAdmin])
```

#### 实时刷新
考虑添加定时自动刷新列表（可选）：
```typescript
useEffect(() => {
  const interval = setInterval(() => {
    if (hasProcessingArticles) {
      fetchArticles()
    }
  }, 30000) // 每 30 秒刷新一次

  return () => clearInterval(interval)
}, [hasProcessingArticles])
```

## 最佳实践

### 1. 批量创建文章后
- 一次不要创建太多文章（建议 10-20 篇）
- 等待第一批完成后再创建更多
- 定期检查处理进度

### 2. 监控 AI 配额
- DeepSeek：每天检查使用量
- OpenAI：监控账户余额
- 图片 API：检查请求限制

### 3. 错误处理
- 查看日志文件了解失败原因
- 常见错误：
  - `timeout`：API 超时，重试即可
  - `rate_limit`：请求过快，等待后重试
  - `insufficient_quota`：配额不足，需要充值或等待重置

### 4. 内容质量检查
AI 生成完成后：
- 检查图片是否正确加载
- 验证内容质量
- 确保 SEO 元数据正确
- 手动调整发布时间（如需要）

## 故障排除

### 问题：文章一直显示"处理中"
**解决方案**：
1. 检查 API 密钥是否有效
2. 使用重置按钮清空并重新生成
3. 查看服务器日志了解具体错误

### 问题：图片搜索失败
**解决方案**：
1. 检查 Pixabay/Pexels/Unsplash API 密钥
2. 确保网络可以访问这些 API
3. 考虑手动添加图片

### 问题：内容质量差
**解决方案**：
1. 调整 AI 提示词（`AI_GENERATE_PROMPT`）
2. 尝试不同的模型
3. 手动编辑内容

### 问题：频繁失败
**解决方案**：
1. 降低并发处理数量
2. 增加 API 超时时间（如果使用 Pro 版本）
3. 检查网络连接

## 总结

AI 文章处理卡住是一个常见问题，主要由 API 超时引起。通过：
1. 定期监控和重置卡住的文章
2. 优化 API 调用和超时处理
3. 分阶段处理降低超时风险
4. 完善的错误处理和重试机制

可以最大程度减少卡住情况，提高文章生成效率。
