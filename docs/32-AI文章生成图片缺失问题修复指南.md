# AI 文章生成图片缺失问题修复指南

## 问题描述

在 `/api/articles/ai-rewrite` 的文章生成流程中，发现很多文章生成后没有图片，例如文章 ID 214、204 等。根据设计，文章生成应该分两步走：

1. **阶段 1**：DeepSeek 生成文章内容和图片占位符
2. **阶段 2**：根据占位符从 Pixabay/Pexels/Unsplash 搜索图片，然后才正式发布

**现状问题**：很多文章在没有图片的情况下就被正式发布了，违反了两步走的流程设计。

## 问题原因

虽然代码已经实现了一些防护机制，但存在以下问题：

1. **第二层防护不足**：虽然检测到没有占位符会重新生成，但没有阻止无图内容的保存
2. **第三层防护缺失**：当图片搜索全部失败时，只是清理占位符然后发布，而不是重新生成
3. **缺少强制验证**：没有在关键节点强制验证图片存在性

### 为什么文章会没有图片？

文章没有图片可能由以下原因导致：

1. **AI 未生成占位符**：DeepSeek 没有按预期生成图片占位符
2. **占位符被清理**：在图片搜索失败后，占位符被错误地清理
3. **图片搜索失败**：所有图片 API 都无法匹配到图片
4. **直接发布**：在没有验证图片存在的情况下直接发布

### 错误流程示例

**场景 1：AI 未生成占位符**
```
1. AI 生成内容（但没有图片占位符）
2. 保存内容到数据库
3. 后台任务检测到没有占位符
4. 直接发布（❌ 应该重新生成）
```

**场景 2：图片搜索全部失败**
```
1. AI 生成内容（有 3 个占位符）
2. 尝试搜索图片（3 个都失败）
3. 清理所有占位符
4. 发布文章（❌ 应该重新生成）
```

## 解决方案

### 三层防护机制

为了彻底解决文章没有图片就被发布的问题，实现三层防护机制：

#### 第一层：AI 提示词强制要求

在 `AI_GENERATE_PROMPT` 中明确要求 AI 必须生成图片占位符：

```typescript
const AI_GENERATE_PROMPT = `...
## CRITICAL REQUIREMENTS - MUST READ

### Image Placeholders (MANDATORY - DO NOT SKIP)
You MUST include image placeholders in your article. This is a hard requirement.

**EXACT FORMAT to use:**
![Descriptive alt text](IMAGE_PLACEHOLDER_1(search keywords for the image))

**Key rules:**
1. Include EXACTLY 3-5 image placeholders throughout the article
2. Place first image placeholder after the introduction
3. Place remaining placeholders at the start of major sections
4. Keywords should be 2-4 words describing the visual content
5. Alt text should be descriptive and accessible
6. DO NOT use actual image URLs - ONLY use the IMAGE_PLACEHOLDER format

**FINAL REMINDER:** Your article MUST include 3-5 image placeholders in the format. 
Articles without image placeholders will be rejected.
...`
```

**作用**：从源头确保 AI 生成带有图片占位符的内容。

#### 第二层：验证 AI 响应包含占位符

在保存 AI 生成的内容之前，验证是否包含图片占位符：

```typescript
const hasPlaceholders = (article.content && article.content.includes('IMAGE_PLACEHOLDER_'))

if (hasContent && !hasPlaceholders) {
  // 有内容但没有图片占位符 - 这意味着 AI 没有按预期生成占位符
  console.warn(`[第二层防护失败] 文章 ${article.title} 有内容但无图片占位符，需要重新生成`)
  
  // 清空内容并重置为 pending，让 AI 重新生成（带有图片占位符）
  await prisma.article.update({
    where: { id: article.id },
    data: {
      content: '',  // 清空无效内容
      aiRewriteStatus: 'pending',
      aiRewriteAt: new Date()
    }
  })
  
  console.log(`[AI 流水线] 已重置文章 ${article.title} 以重新生成（包含图片占位符）`)
  return { id: article.id, slug: article.slug, title: article.title }
}
```

**作用**：如果 AI 生成的内容没有占位符，不保存内容，强制重新生成。

#### 第三层：确保至少一张图片成功搜索

在图片搜索完成后，验证是否至少成功匹配到一张图片：

```typescript
// 第三层防护：检查是否至少成功上传了一张图片
if (placeholders.length > 0 && successCount === 0) {
  console.error(`[第三层防护失败] 文章 ${article.title} 未能匹配任何图片 (${placeholders.length} 个占位符，0 张成功)`)
  console.error(`[第三层防护] 清空内容，重置为 pending 状态，重新从第一步开始`)
  
  // 清空内容，保留占位符格式，让 AI 重新生成（可能需要不同的关键词）
  await prisma.article.update({
    where: { id: article.id },
    data: {
      content: '',  // 清空内容，强制 AI 重新生成
      aiRewriteStatus: 'pending',
      aiRewriteAt: new Date()
    }
  })
  console.log(`[AI 流水线] 文章 ${article.title} 已清空内容并重置为 pending 状态（需要重新生成）`)
  return { id: article.id, slug: article.slug, title: article.title }
}

console.log(`[第三层防护成功] 文章 ${article.title} 成功匹配 ${successCount}/${placeholders.length} 张图片，继续发布流程`)
```

**作用**：如果所有图片搜索都失败，清空内容并重新生成，而不是发布无图文章。

### 防护机制工作流程

```
开始
  ↓
[第一层] AI 生成内容
  ↓
[第二层] 验证包含占位符
  ├─ 没有 → 清空内容，重新生成
  └─ 有 → 继续
  ↓
[第三层] 搜索并验证图片
  ├─ 全部失败 → 清空内容，重新生成
  └─ 至少 1 张成功 → 发布文章
  ↓
完成
```

### 修复后的行为

#### 场景 1：AI 未生成占位符

1. AI 生成内容（但没有图片占位符）
2. **第二层防护**检测到 `!hasPlaceholders`
3. 清空内容，状态设为 `pending`
4. 返回，等待下次重新生成
5. **结果**：不会保存无占位符的内容

#### 场景 2：图片搜索全部失败

1. AI 生成内容（有 3 个占位符）
2. 第二层防护通过
3. 尝试搜索图片（3 个都失败，`successCount = 0`）
4. **第三层防护**检测到 `successCount === 0`
5. 清空内容，状态设为 `pending`
6. 返回，等待下次重新生成
7. **结果**：不会发布无图文章

#### 场景 3：部分图片搜索成功

1. AI 生成内容（有 3 个占位符）
2. 第二层防护通过
3. 尝试搜索图片（2 个成功，1 个失败）
4. 第三层防护通过（`successCount = 2 > 0`）
5. 替换成功的占位符
6. 生成封面图
7. 发布文章
8. **结果**：文章发布，包含 2 张图片

#### 场景 4：所有图片搜索成功

1. AI 生成内容（有 3 个占位符）
2. 第二层防护通过
3. 尝试搜索图片（3 个都成功）
4. 第三层防护通过（`successCount = 3 > 0`）
5. 替换所有占位符
6. 生成封面图
7. 发布文章
8. **结果**：文章发布，包含 3 张图片

## 相关代码逻辑

### 图片搜索优先级

`searchImage` 函数会按以下顺序尝试搜索图片：

1. Pixabay（免费，优先级最高）
2. Pexels
3. Unsplash

对于每个占位符，会尝试多个搜索关键词组合：

```javascript
const searchSequences = [
  cleanKeywords,              // 占位符中的关键词
  cleanAlt,                   // Alt 文本
  `${cleanKeywords} ${titleWords}`,  // 关键词 + 标题
  titleWords                  // 标题关键词
]
```

### 状态流转

文章的 `aiRewriteStatus` 状态流转：

```
pending → processing → pending/completed → completed
         ↓
       failed → pending（可重试）
```

- `pending`：待处理
- `processing`：处理中
- `completed`：已完成（已发布）
- `failed`：失败（会自动转为 pending 重试）

## 影响和注意事项

### 正面影响

1. ✅ **三层防护**：从源头到发布全程验证，确保文章质量
2. ✅ **零容错机制**：任何环节没有图片都会重新生成
3. ✅ **符合设计流程**：严格遵守两步走的生成流程
4. ✅ **自动重试**：失败的生成会自动进入重试队列
5. ✅ **更好的用户体验**：发布的文章都至少包含 1 张图片
6. ✅ **减少手动干预**：自动修复大多数问题，减少管理员工作量

### 需要注意的事项

1. **部分成功的情况**：如果只有部分图片成功（比如 3 个占位符，1-2 张成功），文章仍然会发布
2. **图片源配置**：需要确保至少配置了一个图片 API（Pixabay、Pexels、Unsplash）
3. **API 配额监控**：需要监控图片 API 的配额 使用情况，避免用尽后导致大量文章无法完成
4. **关键词质量**：如果发现图片搜索频繁失败，可能需要优化 AI 提示词，生成更好的搜索关键词
5. **重复重试**：如果关键词本身有问题，可能会多次重试失败，需要人工介入

### 处理已发布的无图文章

对于已经发布但没有图片的文章（如 ID 214、204 等），建议处理方式：

#### 方案 1：批量重置（推荐）

使用管理界面或脚本批量重置这些文章：

```sql
-- 重置已发布但没有封面图的文章
UPDATE articles 
SET 
  aiRewriteStatus = 'pending',
  content = '',
  coverImage = NULL,
  published = FALSE,
  publishedAt = NULL
WHERE published = TRUE 
  AND (coverImage IS NULL OR coverImage = '')
  AND id IN (214, 204, ...);
```

#### 方案 2：手动补充图片

对于重要的文章，可以手动补充图片：
1. 在编辑页面手动上传封面图
2. 在文章内容中插入图片
3. 保存并发布

#### 方案 3：删除并重新生成

对于质量不高的文章：
1. 删除原文章
2. 重新创建文章标题
3. 让 AI 重新生成（会触发三层防护）

## 总结

通过实现三层防护机制：

1. ✅ **第一层防护**：AI 提示词强制要求生成图片占位符
2. ✅ **第二层防护**：验证 AI 响应是否包含占位符，没有则重新生成
3. ✅ **第三层防护**：确保至少一张图片成功搜索，全部失败则重新生成
4. ✅ **零容错机制**：任何环节没有图片都会重新生成，不会发布无图文章
5. ✅ **自动重试**：失败的生成会自动进入重试队列
6. ✅ **符合设计流程**：严格遵守两步走的生成流程设计
7. ✅ **提升质量**：发布的文章都至少包含 1 张图片
8. ✅ **减少干预**：自动修复大多数问题，减少管理员工作量

这个三层防护机制彻底解决了文章在没有图片的情况下被发布的问题，确保了 AI 生成文章的质量标准，同时通过自动重试机制减少了人工干预的需求。
